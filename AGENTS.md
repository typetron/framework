# Typetron Framework Guide

Read the documentation for the module you are changing before editing its source. Nested features are documented by their owning module; for
example, HTTP and WebSocket routing are covered by Router, while migrations and seeders are covered by Database.

## Module Documentation

- [Cache](Cache/Readme.md) - cache contracts and memory, file, and database stores.
- [Container](Container/Readme.md) - dependency injection, bindings, resolvers, and scopes.
- [Database](Database/Readme.md) - connections, queries, entities, relationships, migrations, and seeders.
- [Encryption](Encryption/Readme.md) - password hashing and JSON Web Tokens.
- [Forms](Forms/Readme.md) - typed input objects and field validation.
- [Framework](Framework/Readme.md) - application bootstrap, configuration, providers, authentication, and middleware.
- [Mail](Mail/Readme.md) - mailables, recipients, and transports.
- [Models](Models/Readme.md) - explicit response and data projections.
- [Router](Router/Readme.md) - controllers, HTTP routes, WebSocket actions, middleware, and servers.
- [Storage](Storage/Readme.md) - files, directories, and image data.
- [Support](Support/Readme.md) - shared types, utilities, and prototype helpers.
- [Testing](Testing/Readme.md) - application-aware HTTP and WebSocket test helpers.
- [Validation](Validation/Readme.md) - built-in and custom validation rules.
- [Angular](Frontend/Angular/Readme.md) - Angular form integration.
- [Browser WebSockets](Frontend/Websockets/Readme.md) - the Typetron WebSocket browser client.

## Working in This Repository

- Treat each capitalized source directory as a framework module.
- Use the nearest module barrel or the documented `@Typetron/<Module>` path for public imports.
- Look for corresponding behavior tests under `tests/<Module>` before changing an implementation.
- Do not edit `build/`; it is generated by `npm run build`.
- Keep module documentation aligned with public behavior. Update the relevant `Readme.md` when an API, default, error, or example changes.
- Keep documentation examples short and executable in shape. Do not document planned or commented-out features as available.
